# LanWash Site

Репозиторий: https://github.com/mixelka75/LanWash-Site

GitHub Pages: https://mixelka75.github.io/LanWash-Site/

Отдельный адаптивный лендинг LanWash на React + TypeScript + Vite. Фирменный логотип, локальный Manrope и реальные экраны Android-демо включены в репозиторий.

## Запуск

Node.js 22.12+ (проверено на 24.19) и pnpm 11.19.

```bash
pnpm install
pnpm dev
```

Страница: http://127.0.0.1:5173. Сервер по умолчанию слушает только localhost. Для просмотра с другого устройства можно явно запустить `pnpm dev --host 0.0.0.0`.

```bash
pnpm build
pnpm preview
```

Готовая статическая сборка находится в `dist/`. Также можно использовать npm; для повторяемой установки зависимостей предпочтителен сохранённый `pnpm-lock.yaml`.

## Что есть на странице

- **Клиентская версия:** карта, бонусы и посещения; пять шагов записи с отдельным мокапом каждого экрана. В клиентской версии нет кабинетов или описаний владельца и сотрудников.
- Кнопка «Зарегистрироваться» объясняет создание аккаунта в Android-приложении. Веб-регистрация через API не подключается: пользователь выбрал регистрацию в приложении.
- Рядом со скачиванием — кнопка «Записаться на сайте / Скоро», ведущая на `https://lanwash.ru`. Она не создаёт запись.
- Галерея клиентской версии показывает только карту и кошелёк. Увеличение — в диалоге.
- Интерактивный пример бонусов: услуга, время, списание и пересчёт денежной части/кешбэка.
- **Бизнес-версия:** отдельная страница с шестью этапами работы — заявка, услуги, команда, запись/сессия, расчёт, аналитика. Подробно описаны три формата моек, бонусные правила, четыре роли, чеки, абонементы и CSV.
- Кнопка «Для бизнеса» переключает на бизнес-версию; «Для клиентов» возвращает обратно.
- Демо-форма доступна в бизнес-версии; телефон проверяется, заявка сохраняется локально в браузере.
- Ссылки верхнего меню имеют область нажатия не менее 48 px по высоте; мобильное меню используется до 960 px.
- Доступные подписи, клавиатурная навигация, Escape/ловушка фокуса в диалогах, поддержка reduced motion.

## Две версии и будущие поддомены

Имена поддоменов пользователь пока отложил. DNS и хостинг отдельных поддоменов не настроены; публикация текущей версии на GitHub Pages запускается после push в `main`.

Локальное превью: клиентская версия — `/`, бизнес — `/?audience=business`. На текущем GitHub Pages работает тот же способ переключения после отдельной публикации. Пока адреса не заданы, ссылки меняют `audience` на том же сайте.

Для двух независимых статических сайтов:

```bash
pnpm build:subdomains
```

Результат: `dist/clients/` и `dist/business/`. Каждый каталог размещается в корне своего поддомена. Аудитория и метаданные страницы заданы при сборке; клиентская версия открывается по умолчанию.

Перед сборкой укажите в `.env.local` выбранные адреса:

```dotenv
VITE_CLIENT_SITE_URL=https://<клиентский-поддомен>
VITE_BUSINESS_SITE_URL=https://<бизнес-поддомен>
```

Параметр `?audience=clients` / `?audience=business` позволяет проверить обе версии локально. Для индивидуальной сборки есть `pnpm build:clients` и `pnpm build:business`.

## Заглушки

Пользователь попросил пока оставить реальные контакты и ссылку на APK заглушками.

- `src/config.ts` — состояние контактов и ссылки.
- `.env.example` — `VITE_ANDROID_DOWNLOAD_URL`. Если пусто, кнопка открывает честную заглушку; после указания URL появится ссылка на APK.
- Заявка **не отправляется** на сервер. Она сохраняется в `localStorage` под ключом `lanwash-business-draft`, и интерфейс сообщает об этом. Для реальных заявок нужно заменить обработчик `BusinessForm` в `src/App.tsx` и согласовать правила работы с контактными данными.
- Нет внешней аналитики, CDN-шрифтов, API-запросов или скрытой отправки формы.

## Структура

- `src/App.tsx` — клиентская страница, общая навигация, диалоги и интерактивные блоки.
- `src/BookingGuide.tsx` / `src/booking-guide.css` — инструкция записи и пять мокапов.
- `src/BusinessPage.tsx` / `src/business.css` — бизнес-версия.
- `src/styles.css` — дизайн и адаптивные состояния.
- `src/config.ts` — аудитория, ссылки двух сайтов, регистрация через приложение и контактный статус.
- `.env.clients` / `.env.business` — режимы сборки двух сайтов.
- `public/images/` — логотип и оптимизированные WebP-скриншоты.
- `public/fonts/` — Manrope и OFL.
- `docs/VERIFICATION.md` — результаты проверки.

Данные на изображениях демонстрационные. Мокапы инструкции обозначены как примеры экранов; последовательность, цены и длительность сверены с актуальным `LanWash-Android`. Скриншоты карты содержат данные © [OpenStreetMap contributors](https://www.openstreetmap.org/copyright). Логотип предоставлен пользователем. Manrope — [OFL](public/fonts/OFL.txt). Иконки — Lucide.

Android-репозиторий: https://github.com/mixelka75/LanWash-Android. В этой репе нет Android-исходников или APK.

## GitHub Pages

Публикация настроена через `.github/workflows/pages.yml`: после push в `main` устанавливаются зависимости из lockfile, выполняется сборка и публикуется `dist/`.

```bash
pnpm build:pages
pnpm preview --base=/LanWash-Site/
```

Для этой сборки локальный адрес: `http://127.0.0.1:4173/LanWash-Site/`. Параметр Vite `--base=/LanWash-Site/` обеспечивает корректные пути к JS, CSS, изображениям и шрифтам. Обычные `pnpm dev` / `pnpm build` по-прежнему работают в корне для локальной разработки.

Публикуется только статический сайт. Контакты/APK остаются заглушками, форма не отправляет заявки.
