# LanWash — лендинг

Сайт **[lanwash.ru](https://lanwash.ru)** — лендинг Android-приложений LanWash. Сделан на React, TypeScript и Vite. Логотип, шрифт Manrope и скриншоты приложения лежат в репозитории, внешних CDN нет. Единственный сторонний скрипт — Яндекс Метрика, и только после согласия посетителя (см. «Cookie и Яндекс Метрика»).

На сайте две версии:

| Версия     | Адрес                                                                  | Для кого                                                       |
| ---------- | ---------------------------------------------------------------------- | -------------------------------------------------------------- |
| Клиентская | [lanwash.ru](https://lanwash.ru)                                       | водители: приложение «LanWash» (`ru.lanwash.app`)              |
| Бизнес     | [lanwash.ru/?audience=business](https://lanwash.ru/?audience=business) | автомойки: приложение «LanWash Бизнес» (`ru.lanwash.business`) |

## Сборка

Нужны Node.js 22.12+ и pnpm 11.19.

```bash
pnpm install
pnpm dev          # разработка
npm run build     # проверка типов и сборка в dist/
```

Пути в сборке относительные: папку `dist/` можно разместить на любом статическом хостинге. Документы `public/terms.html` и `public/privacy.html` — обычный HTML, в сборку они копируются как есть.

Отдельные сборки двух версий — например, если версии переедут на разные поддомены:

```bash
pnpm build:subdomains   # dist/clients/ и dist/business/
```

Адреса поддоменов задаются в `.env.local`: `VITE_CLIENT_SITE_URL`, `VITE_BUSINESS_SITE_URL`. Пока они не заданы, «Для бизнеса» и «Для клиентов» переключают версию на том же сайте.

## Деплой на сервер

Push в `main` запускает `.github/workflows/deploy.yml`: сначала выполняется production-сборка, затем задание `deploy` ждёт ручного подтверждения в GitHub. Только после него сборка отправляется по SSH на сервер. GitHub Pages для боевого сайта не используется.

В **Settings → Environments → production** включите **Required reviewers** и добавьте человека, который подтверждает публикацию. URL среды — `https://lanwash.ru`.

Секреты репозитория:

| Секрет | Значение |
| --- | --- |
| `DEPLOY_HOST` | адрес сервера |
| `DEPLOY_USER` | SSH-пользователь с правом записи в каталог сайта |
| `DEPLOY_PATH` | абсолютный каталог, например `/var/www/lanwash` |
| `DEPLOY_SSH_KEY` | приватный ключ для входа |
| `DEPLOY_KNOWN_HOSTS` | результат `ssh-keyscan <сервер>` для проверки сервера |

Переменная `DEPLOY_HEALTHCHECK_URL` в **Settings → Variables** необязательна; по умолчанию проверяется `https://lanwash.ru`.

Каждая сборка распаковывается в `DEPLOY_PATH/releases/<commit>`, а symlink `DEPLOY_PATH/current` атомарно переключается на неё. В nginx корень сайта должен указывать на текущий релиз:

```nginx
root /var/www/lanwash/current;
```

После публикации workflow проверяет сайт по HTTPS. Если проверка не прошла, symlink возвращается на предыдущий релиз. Для ручного отката переключите `current` на нужный каталог в `releases/`.

## Что на странице

**Клиентская версия:**

- хиро с экраном «Вы записаны», кнопками «Скачать в RuStore» и «Записаться на сайте» (`https://app.lanwash.ru`);
- **«Как записаться» — шесть шагов**, на каждом настоящий экран приложения:
  1. карта;
  2. карточка мойки;
  3. услуги и время;
  4. проверка записи;
  5. записи с QR для кассы;
  6. кошелёк с бонусами после визита;
- «Чаще заезжаете. Больше получаете.» — кошелёк сети и расчёт визита в стиле приложения: можно переключить услугу и списание бонусов;
- «Экраны приложения» — переключатель всех десяти клиентских экранов, от карты до профиля;
- вопросы и ответы, поддержка и документы.

**Бизнес-версия** (в шапке — «LanWash.Бизнес»):

- экраны владельца и кассира;
- шесть этапов работы мойки, бонусные правила, роли, вопросы;
- **«Подключить мойку» — анкета на сайте**, те же четыре шага, что в «LanWash Бизнес»: мойка, услуги и цены, оформление и фото, контакты и проверка.
  - Фото загружаются в `POST /v1/media`, заявка уходит в `POST /v1/wash-applications` на сервер LanWash (`VITE_API_URL`).
  - Номера заявок сохраняются в этом браузере (`localStorage`, ключ `lanwash.wash-applications`). Если снова открыть анкету, она покажет статус заявки.
  - Временный пароль владельца выдаётся **один раз**. В ответе на `POST /v1/wash-applications` приходит `claimToken`; он хранится рядом с id заявки. Когда `GET /v1/wash-applications?ids=` вернёт `credentialsReady: true`, в карточке появится «Получить пароль» → `POST /v1/wash-applications/{id}/credentials` с `{"claimToken": "…"}`. Пароль показывается с кнопкой копирования и живёт только в памяти, пока открыто окно; токен сразу удаляется. На `410` показывается текст сервера, токен тоже удаляется; новый пароль выдаёт администратор.
  - Токен удаляется и тогда, когда он уже не нужен: заявка отклонена или пароль выдан/истёк (`credentialsReady: false`).
  - Серверу нужен CORS для адреса сайта. Анкета отправляет JSON, поэтому браузер сначала делает запрос `OPTIONS`.

**Общее для обеих версий:**

- «Скачать в RuStore» ведёт на карточку нужного приложения;
- в футере — «Android 8.0+» и бейдж возрастной маркировки «0+»; подробности о возрасте — в документах;
- иконки — линейные, цвета текста, в плашках с тонкой рамкой; цветом выделены только активные состояния и кнопки.

## Cookie и Яндекс Метрика

Счётчик 114175626 подключается из `src/analytics.ts`, а не кодом в `index.html`:

- пока посетитель не нажал «Разрешить» в плашке (`src/CookieNotice.tsx`), запросов к `mc.yandex.ru` и cookie `_ym_*` нет; пикселя `<noscript>` нет — без JavaScript согласие не спросить;
- выбор (`granted` / `denied`) хранится в `localStorage` под ключом `lanwash.analytics-consent` 12 месяцев, затем плашка появится снова; отказ тоже запоминается;
- «Настройки cookie» в футере или ссылка `./#cookie-settings` открывают плашку снова; при отказе после согласия сайт удаляет cookie `_ym_*` со своего домена и перезагружается без счётчика;
- настройки счётчика: `webvisor: false`, `clickmap: true`, `trackLinks: true`, `accurateTrackBounce: true`, `disableYtm: true`; `ecommerce` и `params` не передаются. Анкета дополнительно помечена классом `ym-hide-content` на случай, если Вебвизор когда-нибудь включат.

Если меняете настройки счётчика, обновите `privacy.html` (разделы 2–6) и `consent.html#analytics`. В интерфейсе Метрики Вебвизор тоже должен быть выключен.

## Шрифт

`public/fonts/manrope.woff2` — вариативный Manrope (ось `wght` 200–800), подмножество: латиница (U+0000–00FF и типографские знаки), кириллица (U+0400–045F, Ґ, Ұ, №), ₽, стрелки ← ↑ → ↓, минус. Это все символы, которые есть на сайте и в документах. Файл один, а не два по `unicode-range`: на каждой странице есть и кириллица, и латиница с цифрами, так что два файла дали бы лишний запрос без экономии. `unicode-range` в `@font-face` (`src/styles.css`, `public/legal.css`) описывает, что в файле есть: остальные символы браузер возьмёт из Arial, не скачивая шрифт.

Было: `manrope.ttf` 164,7 КБ. Стало: `manrope.woff2` 32,7 КБ.

Лицензия — SIL OFL 1.1 (`public/fonts/OFL.txt`, лежит рядом со шрифтом и попадает в сборку). У Manrope нет Reserved Font Name, поэтому подмножество можно распространять под тем же именем; в таблице `name` сохранены копирайт и ссылка на лицензию. Продавать сам шрифт отдельно нельзя, производные — только под OFL.

Пересобрать (исходный TTF — в истории git, fonttools ставится во временное окружение, не в проект):

```bash
git show f73135d:public/fonts/manrope.ttf > /tmp/manrope.ttf
python3 -m venv /tmp/fontenv && /tmp/fontenv/bin/pip install fonttools brotli
/tmp/fontenv/bin/pyftsubset /tmp/manrope.ttf --flavor=woff2 --layout-features='*' \
  --name-IDs='*' --name-languages='*' --output-file=public/fonts/manrope.woff2 \
  --unicodes='U+0000-00FF,U+0131,U+0152-0153,U+02BB-02BC,U+02C6,U+02DA,U+02DC,U+0301,U+0304,U+0308,U+0329,U+0400-045F,U+0490-0491,U+04B0-04B1,U+2000-206F,U+20AC,U+20BD,U+2116,U+2122,U+2190-2193,U+2212,U+2215,U+FEFF,U+FFFD'
```

Если на сайте появятся новые символы (например, казахские буквы), добавьте их в `--unicodes` и в оба `unicode-range`.

## Страницы ошибок

`public/404.html` и `public/50x.html` — в стиле документов, со ссылкой на главную. Ссылки и стили ведут к корню сайта, даже если страницу отдали по глубокому адресу: это делает единственный inline-скрипт сайта (`<base>` для подпапки GitHub Pages). Стили страниц — в `legal.css`, кнопка «Обновить страницу» работает через `legal.js`, без inline-обработчика.

- **GitHub Pages и Cloudflare Pages** отдают `404.html` сами.
- **nginx** — см. `deploy/nginx/lanwash.ru.conf`: `error_page` стоит внутри `location /`, поэтому ответы `/v1/` и `/pay/` (в том числе 502, когда бэкенд недоступен) остаются как есть, а не подменяются HTML-страницей.

## nginx

`deploy/nginx/lanwash.ru.conf` — шаблон конфига lanwash.ru. На сервере он не применён. Что в нём:

| Что                      | Значение                                                                                                                                                                            |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HSTS                     | `max-age=31536000`, без `includeSubDomains` — включить, когда все поддомены точно на HTTPS                                                                                          |
| CSP                      | только свои файлы + Яндекс Метрика (`mc.yandex.*` из [официального списка](https://yandex.ru/support/metrica/code/install-counter-csp.html), `yastatic.net`); без `'unsafe-inline'` |
| `X-Content-Type-Options` | `nosniff`                                                                                                                                                                           |
| `Referrer-Policy`        | `strict-origin-when-cross-origin`                                                                                                                                                   |
| `Permissions-Policy`     | камера, микрофон, геопозиция, датчики, платежи, USB, Topics — запрещены                                                                                                             |
| Кэш                      | `/assets/` — год, `immutable`; HTML, `theme.js`, `legal.*` — `no-cache`; шрифт — неделя; картинки и favicon — сутки                                                                 |
| Ошибки                   | 404/50x для статики                                                                                                                                                                 |
| `/v1/`, `/pay/`          | `include snippets/lanwash-api.conf` — прокси на `127.0.0.1:8080` не меняется; из новых заголовков к ним добавляется только HSTS                                                     |

Почему CSP такая:

- `script-src 'self' https://mc.yandex.ru https://yastatic.net` — сборка, `tag.js` Метрики и её модули. Inline-скриптов на страницах нет: тема ставится файлом `theme.js`, счётчик — из бандла после согласия.
- `img-src` — `blob:` для превью фото в анкете и пиксели Метрики; `connect-src` — API анкеты (`https://lanwash.ru` указан явно для посетителей с `www.lanwash.ru`) и отправка данных Метрики; `frame-src` — фрейм синхронизации Метрики (`match.html`).
- `frame-ancestors` — свой сайт и домены интерфейса Метрики: карта кликов открывает сайт во фрейме. `X-Frame-Options` не ставится, его заменяет `frame-ancestors`.
- `mc.webvisor.*` и `wss://` из списка Яндекса не включены: они нужны Вебвизору, а он выключен. Включите Вебвизор — добавьте их.
- Для 404/50x своя политика: их inline-скрипт разрешён по `sha256`. После правки скрипта пересчитайте хеш и замените его в двух строках карты `$lanwash_csp`:

```bash
python3 -c "import re,hashlib,base64;s=open('public/404.html',encoding='utf-8').read();b=re.search(r'<script>(.*?)</script>',s,re.S).group(1);print('sha256-'+base64.b64encode(hashlib.sha256(b.encode()).digest()).decode())"
```

Как применить на сервере:

1. Сохраните текущий файл: `sudo cp /etc/nginx/sites-available/lanwash.ru ~/lanwash.ru.conf.bak`.
2. Сравните с шаблоном. Строки `# managed by Certbot` и `root` оставьте как на сервере (при выкладке релизами — `root /var/www/lanwash/current;`). Карты `map` должны остаться вне `server { }`.
3. Скопируйте файл, проверьте и перезагрузите: `sudo nginx -t && sudo systemctl reload nginx`.
4. Проверьте заголовки: `curl -sI https://lanwash.ru/ | grep -iE 'content-security|strict-transport|cache-control'`, `curl -sI https://lanwash.ru/assets/<файл>.js` (должно быть `immutable`), `curl -sI https://lanwash.ru/v1/…` (CSP и `Cache-Control` от nginx быть не должно).
5. Откройте сайт, нажмите «Разрешить» в плашке cookie и проверьте в DevTools, что в консоли нет ошибок CSP, а запросы к `mc.yandex.ru` проходят.
6. Если что-то сломалось — верните копию из шага 1 и снова `nginx -t && systemctl reload nginx`.

Шаблон проверен `nginx -t` на nginx 1.22 и текущем stable (на новых версиях `listen … http2` выдаёт предупреждение — можно заменить на `http2 on;`); заголовки по всем типам адресов сверены curl’ом на тестовом контейнере.
