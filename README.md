# LanWash — лендинг

Сайт **[lanwash.ru](https://lanwash.ru)** — лендинг Android-приложений LanWash. Сделан на React, TypeScript и Vite. Логотип, шрифт Manrope и скриншоты приложения лежат в репозитории; внешних CDN, cookie, счётчиков и форм нет.

На сайте две версии:

| Версия | Адрес | Для кого |
| --- | --- | --- |
| Клиентская | [lanwash.ru](https://lanwash.ru) | водители: приложение «LanWash» (`ru.lanwash.app`) |
| Бизнес | [lanwash.ru/?audience=business](https://lanwash.ru/?audience=business) | автомойки: приложение «LanWash Бизнес» (`ru.lanwash.business`) |

## Сборка

Нужны Node.js 22.12+ и pnpm 11.19.

```bash
pnpm install
pnpm dev          # разработка
npm run build     # проверка типов и сборка в dist/
```

Пути в сборке относительные: папку `dist/` можно разместить на любом статическом хостинге. Документы `public/terms.html` и `public/privacy.html` — обычный HTML, в сборку они копируются как есть.

Отдельные сборки двух версий — например, если версии переедут на разные поддомены:

```bash
pnpm build:subdomains   # dist/clients/ и dist/business/
```

Адреса поддоменов задаются в `.env.local`: `VITE_CLIENT_SITE_URL`, `VITE_BUSINESS_SITE_URL`. Пока они не заданы, «Для бизнеса» и «Для клиентов» переключают версию на том же сайте.

## Деплой на сервер

Push в `main` запускает `.github/workflows/deploy.yml`: сначала выполняется production-сборка, затем задание `deploy` ждёт ручного подтверждения в GitHub. Только после него сборка отправляется по SSH на сервер. GitHub Pages для боевого сайта не используется.

В **Settings → Environments → production** включите **Required reviewers** и добавьте человека, который подтверждает публикацию. URL среды — `https://lanwash.ru`.

Секреты репозитория:

| Секрет | Значение |
| --- | --- |
| `DEPLOY_HOST` | адрес сервера |
| `DEPLOY_USER` | SSH-пользователь с правом записи в каталог сайта |
| `DEPLOY_PATH` | абсолютный каталог, например `/var/www/lanwash` |
| `DEPLOY_SSH_KEY` | приватный ключ для входа |
| `DEPLOY_KNOWN_HOSTS` | результат `ssh-keyscan <сервер>` для проверки сервера |

Переменная `DEPLOY_HEALTHCHECK_URL` в **Settings → Variables** необязательна; по умолчанию проверяется `https://lanwash.ru`.

Каждая сборка распаковывается в `DEPLOY_PATH/releases/<commit>`, а symlink `DEPLOY_PATH/current` атомарно переключается на неё. В nginx корень сайта должен указывать на текущий релиз:

```nginx
root /var/www/lanwash/current;
```

После публикации workflow проверяет сайт по HTTPS. Если проверка не прошла, symlink возвращается на предыдущий релиз. Для ручного отката переключите `current` на нужный каталог в `releases/`.

## Что на странице

**Клиентская версия:**
- хиро с экраном «Вы записаны», кнопками «Скачать в RuStore» и «Записаться на сайте — скоро»;
- **«Как записаться» — шесть шагов**, на каждом настоящий экран приложения:
  1. карта;
  2. карточка мойки;
  3. услуги и время;
  4. проверка записи;
  5. записи с QR для кассы;
  6. кошелёк с бонусами после визита;
- «Чаще заезжаете. Больше получаете.» — кошелёк сети и расчёт визита в стиле приложения: можно переключить услугу и списание бонусов;
- «Экраны приложения» — переключатель всех десяти клиентских экранов, от карты до профиля;
- вопросы и ответы, поддержка и документы.

**Бизнес-версия** (в шапке — «LanWash.Бизнес»):
- экраны владельца и кассира;
- шесть этапов работы мойки, бонусные правила, роли, вопросы;
- **«Подключить мойку» — анкета на сайте**, те же четыре шага, что в «LanWash Бизнес»: мойка, услуги и цены, оформление и фото, контакты и проверка.
  - Фото загружаются в `POST /v1/media`, заявка уходит в `POST /v1/wash-applications` на сервер LanWash (`VITE_API_URL`).
  - Номера заявок сохраняются в этом браузере. Если снова открыть анкету, она покажет статус заявки, а после одобрения — логин и временный пароль владельца.
  - Серверу нужен CORS для адреса сайта. Анкета отправляет JSON, поэтому браузер сначала делает запрос `OPTIONS`.

**Общее для обеих версий:**
- «Скачать в RuStore» ведёт на карточку нужного приложения;
- в футере — «Android 8.0+» и бейдж возрастной маркировки «0+»; подробности о возрасте — в документах;
- иконки — линейные, цвета текста, в плашках с тонкой рамкой; цветом выделены только активные состояния и кнопки.

## Документы

`public/terms.html` (пользовательское соглашение) и `public/privacy.html` (политика конфиденциальности по 152-ФЗ) описывают, как работает сервис:
- аккаунт и данные на сервере LanWash в России;
- визит оплачивается на кассе мойки, абонемент — картой через ЮKassa;
- бонусы в сети мойки;
- карта Яндекс MapKit;
- возрастная маркировка «0+» и аккаунт с 14 лет.

Оператор — Смигунов Евгений Дмитриевич, физическое лицо. Почта для обращений — `support@lanwash.ru`. Редакция от 29 октября 2026 г.; при изменениях обновите дату в начале обоих документов.

## Страницы ошибок

`public/404.html` и `public/50x.html` — в стиле документов, со ссылкой на главную. Ссылки и стили ведут к корню сайта, даже если страницу отдали по глубокому адресу.
- **GitHub Pages и Cloudflare Pages** отдают `404.html` сами.
- **nginx** — в блок `server` сайта:

```nginx
error_page 404 /404.html;
error_page 500 502 503 504 /50x.html;
location = /404.html { internal; }
location = /50x.html { internal; }
```

Ответы API (`/v1/`, `/pay/`) эти страницы не подменяют, пока для их `location` не включён `proxy_intercept_errors`.

## Структура

- `src/App.tsx` — клиентская версия, шапка, футер, диалоги, раздел «Экраны приложения».
- `src/BookingGuide.tsx`, `src/booking-guide.css` — шесть шагов записи.
- `src/BusinessPage.tsx`, `src/business.css` — бизнес-версия.
- `src/ApplyForm.tsx` — анкета подключения мойки.
- `src/DevicePhone.tsx`, `src/device-phone.css` — рамка Galaxy A17 для скриншотов.
- `src/styles.css` — общий дизайн и адаптивная вёрстка.
- `src/config.ts` — версия сайта, адрес сервера, ссылки RuStore, почта поддержки, возрастная маркировка.
- `public/` — документы, страницы ошибок, изображения, шрифты, favicon.

Карта на скриншотах — Яндекс Карты, их логотип виден в кадре. Шрифт Manrope — [OFL](public/fonts/OFL.txt). Иконки — Lucide.
